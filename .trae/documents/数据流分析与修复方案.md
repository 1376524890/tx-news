# 数据流分析与修复方案

## 🔍 问题诊断结果

### 发现的问题

#### 1. **前端最新信号只显示"深分析完成"**

**根本原因**：数据库中最新信号几乎全部是 `deep_analysis_updated` 类型

数据库查询结果显示：
- 最新 20 条信号中：19 条是 `deep_analysis_updated`，1 条是 `analysis_updated`，1 条是 `breaking`
- 这说明系统主要生成的是深度分析更新信号

#### 2. **Dashboard 界面除知识图谱外其他板块数据不更新**

**可能的原因**：
1. **时间窗口问题**：默认 12 小时窗口可能不包含新数据
2. **数据更新频率**：信号生成频率较低，导致用户感觉"不更新"
3. **信号类型单一**：主要生成 `deep_analysis_updated` 信号

## 🔧 修复方案

### 方案 1：检查信号生成逻辑

检查后端信号生成代码，确保生成多种类型的信号：

```bash
# 查找信号生成相关代码
grep -r "deep_analysis_updated" apps/ --include="*.py"
grep -r "analysis_updated" apps/ --include="*.py"
grep -r "insert_signal" apps/ --include="*.py"
```

### 方案 3：增加数据更新频率

检查 Worker 和 Collector 配置，确保数据定期更新：

```bash
# 检查 Celery Beat 调度配置
grep -r "beat_schedule" apps/ --include="*.py"

# 检查 Collector 配置
cat apps/collector/main.py | grep -A 10 "def main"
```

## 📋 执行步骤

1. **检查信号生成代码**
   - 查找 `insert_signal` 函数调用
   - 分析信号生成逻辑
   - 确认是否应该生成多种类型的信号

2. **检查数据更新配置**
   - 查看 Celery Beat 调度配置
   - 查看 Collector 运行频率
   - 确认数据更新周期

3. **根据发现的问题进行修复**
   - 如果信号生成逻辑有问题，修复信号生成代码
   - 如果数据更新频率低，调整调度配置

4. **验证修复效果**
   - 重启服务
   - 检查前端是否显示多种类型的信号
   - 检查 Dashboard 数据是否正常更新
