# 端口适配调整方案

## 问题诊断

Vite 代理配置正确（代理到 18000），但日志显示连接被拒绝。当前 API 在 18000 正常工作。

## 调整方案

### 方案 1：重启服务（推荐）

```bash
# 1. 停止所有服务
bash scripts/stop_local.sh

# 2. 重新启动
bash scripts/start_local.sh
```

### 方案 2：检查并修复环境变量

检查 `.env` 文件中的端口配置：
```bash
# 确保 .env 中没有冲突的端口配置
# TXNEWS_API_PORT 应该为空或 18000
# TXNEWS_LOCAL_API_PORT 应该为 18000
```

### 方案 3：手动重启 API 和 Vite

```bash
# 1. 停止 API 和 Vite
pkill -f "uvicorn apps.api.main"
pkill -f "vite"

# 2. 等待几秒
sleep 2

# 3. 先启动 API（确保先准备好）
cd /home/codeserver/tx-news
TXNEWS_API_PORT=18000 nohup .venv/bin/uvicorn apps.api.main:app --host 0.0.0.0 --port 18000 > var/log/local/api.log 2>&1 &

# 4. 等待 API 启动
sleep 3

# 5. 再启动 Vite
TXNEWS_API_PORT=18000 nohup npm --prefix apps/web run dev -- --mode public --host 0.0.0.0 --port 8000 --strictPort > var/log/local/web_dev.log 2>&1 &
```

### 方案 4：修改 Vite 配置为固定端口

如果环境变量不稳定，可以直接修改 [vite.config.ts](file:///home/codeserver/tx-news/apps/web/vite.config.ts)：

```typescript
const apiBase = `http://localhost:18000`  // 固定为 18000
```

### 方案 5：检查是否有端口冲突

```bash
# 检查是否有其他进程占用 18000
lsof -i :18000

# 如果有其他进程，杀掉它们
lsof -ti :18000 | xargs kill -9
```

## 验证步骤

执行调整后，验证：
1. 检查 `var/log/local/web_dev.log` 是否还有连接错误
2. 在浏览器中打开 `http://localhost:8000`
3. 查看前端是否能正常加载数据
4. 打开浏览器开发者工具 Network 标签，检查 API 请求是否成功

## 推荐执行顺序

1. **先执行方案 1**（完全重启）
2. 如果问题仍存在，执行方案 2（检查环境变量）
3. 如果仍有问题，执行方案 4（固定端口配置）
