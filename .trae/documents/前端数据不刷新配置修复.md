# 前端数据不刷新 - 配置修复方案

## 🔍 问题诊断结果

### 核心问题
**Vite 代理连接失败**：Vite dev server 无法连接到 API 后端（18000 端口）

### 根本原因分析

1. **环境变量缺失**：
   - `.env` 文件中没有设置 `TXNEWS_API_PORT`、`TXNEWS_WEB_DEV_PORT`、`TXNEWS_LOCAL_API_PORT`
   - Vite 配置依赖 `process.env.TXNEWS_API_PORT`，但该变量未定义

2. **进程启动顺序问题**：
   - `web_dev.log` 显示 Vite 多次重启
   - 每次重启后都出现 `ECONNREFUSED 127.0.0.1:18000` 错误
   - 说明 Vite 启动时 API 还未准备好

3. **配置不一致**：
   - `start_local.sh` 脚本设置 `API_PORT` 和 `WEB_DEV_PORT` 变量
   - 但这些变量没有传递到 Vite 进程环境
   - Vite 使用默认值 18000，但可能 API 在不同端口

## 🔧 修复方案

### 方案 1：在 .env 文件中添加端口配置（推荐）

在 `/home/codeserver/tx-news/.env` 文件末尾添加：

```bash
# API 端口配置
TXNEWS_API_PORT=18000
TXNEWS_ADMIN_PORT=8001
TXNEWS_WEB_DEV_PORT=8000
TXNEWS_LOCAL_API_PORT=18000
```

### 方案 2：修改 vite.config.ts 使用默认端口

修改 `/home/codeserver/tx-news/apps/web/vite.config.ts`：

```typescript
const apiPort = process.env.TXNEWS_API_PORT || '8000'  // 改为 8000
const adminPort = process.env.TXNEWS_ADMIN_PORT || '8001'
const apiBase = `http://localhost:${apiPort}`
const adminBase = `http://localhost:${adminPort}`
```

### 方案 3：修改 start_local.sh 确保环境变量传递

修改 `/home/codeserver/tx-news/scripts/start_local.sh` 中的 Vite 启动部分：

```bash
start_bg_env web_dev \
    TXNEWS_API_PORT="${API_PORT}" \
    TXNEWS_ADMIN_PORT="${ADMIN_PORT}" \
    TXNEWS_WEB_DEV_PORT="${WEB_DEV_PORT}" \
    npm --prefix apps/web run dev -- --mode "${WEB_DEV_MODE}" --host 0.0.0.0 --port "${WEB_DEV_PORT}" --strictPort
```

### 方案 4：添加 API 就绪检查（增强稳定性）

在 `start_local.sh` 中 Vite 启动前添加 API 等待：

```bash
# Wait for API to be ready before starting Vite
wait_http "http://127.0.0.1:${API_PORT}/health" "API /health" 30
```

## 📋 推荐执行步骤

1. **备份当前配置**：
   ```bash
   cp /home/codeserver/tx-news/.env /home/codeserver/tx-news/.env.backup
   cp /home/codeserver/tx-news/scripts/start_local.sh /home/codeserver/tx-news/scripts/start_local.sh.backup
   ```

2. **修改 .env 文件**：添加端口配置（方案 1）

3. **修改 vite.config.ts**：调整默认端口为 8000（方案 2）

4. **修改 start_local.sh**：确保环境变量传递和 API 就绪检查（方案 3 + 4）

5. **重启服务**：
   ```bash
   bash /home/codeserver/tx-news/scripts/stop_local.sh
   bash /home/codeserver/tx-news/scripts/start_local.sh
   ```

6. **验证修复**：
   - 检查 `var/log/local/web_dev.log` 是否还有 `ECONNREFUSED` 错误
   - 在浏览器中访问 `http://localhost:8000` 查看数据是否刷新
   - 打开浏览器开发者工具 Network 标签，检查 API 请求是否成功

## ⚠️ 注意事项

1. **端口冲突**：确保 8000、8001、18000 端口没有被其他程序占用
2. **环境变量优先级**：`.env` 文件中的变量会覆盖默认值
3. **重启顺序**：先停止所有服务，再按正确顺序启动
4. **日志监控**：重启后持续监控日志，确保没有新的错误
