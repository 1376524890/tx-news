# 前端数据不刷新诊断与修复计划

## 诊断步骤

### 1. 检查服务运行状态
- 检查各进程是否正常运行（API、Worker、Beat、NATS Bridge、Collector、Web Dev）
- 查看进程日志文件（`var/log/local/` 目录）
- 检查端口占用情况

### 2. 测试 API 连接
- 测试 Vite dev server (8000 端口) 是否可访问
- 测试 API 后端 (18000 端口) 是否可访问
- 测试关键 API 端点：
  - `/status` - 系统状态
  - `/signals` - 信号列表
  - `/dashboard/summary` - 看板数据
  - `/kg/graph` - 知识图谱数据

### 3. 检查浏览器网络请求
- 打开浏览器开发者工具 (F12)
- 查看 Network 标签页
- 检查 API 请求是否发送
- 查看请求状态码和响应内容
- 检查是否有 CORS 或其他错误

### 4. 检查环境配置
- 验证 `.env` 文件配置
- 检查端口配置是否正确
- 验证代理配置

### 5. 检查后端日志
- 查看 `var/log/local/api.log` 中的错误
- 查看数据库连接状态
- 检查是否有异常或崩溃

## 修复方案（根据诊断结果）

### 方案 A：API 连接问题
- 重启 API 服务
- 检查并修复端口配置
- 验证 Vite 代理配置

### 方案 B：后端服务问题
- 重启后端服务
- 修复数据库连接问题
- 检查依赖服务（Postgres、Redis、Qdrant）

### 方案 C：前端轮询问题
- 验证前端轮询代码是否正常执行
- 检查浏览器控制台是否有 JavaScript 错误
- 必要时调整轮询间隔

### 方案 D：缓存问题
- 清除浏览器缓存
- 验证 API 响应头中的 Cache-Control 设置
- 添加时间戳参数绕过缓存

## 执行命令

```bash
# 1. 检查进程状态
ps aux | grep -E "(uvicorn|celery|vite|nats_bridge|collector)" | grep -v grep

# 2. 检查端口占用
netstat -tlnp | grep -E "(8000|18000|8001|5432|6379|4222|9000|6333)"

# 3. 查看日志
tail -n 50 var/log/local/api.log
tail -n 50 var/log/local/web_dev.log
tail -n 50 var/log/local/worker.log

# 4. 测试 API 端点
curl -s http://localhost:18000/health
curl -s http://localhost:18000/status | jq .
curl -s http://localhost:8000/ | head -20

# 5. 检查环境变量
cat .env | grep -E "(PORT|URL|DSN)"
```

## 预期输出

- 进程运行状态列表
- 端口占用情况
- API 响应内容
- 日志中的错误信息
- 浏览器网络请求截图或描述
